The Spec Is the Bottleneck — deck spec

A five-minute argument in nine slides: the document is the bottleneck, and the fix is a pipeline rather than better prose.

What this solves

Specs are unreadable and untested, and the people who must review them have five minutes of patience for a document that takes thirty.

How it solves it

Nine slides, one idea each, every animation carrying a concept, and a proof slide built from two real screenshots of this very document.

How we prove it

A timed rehearsal under 5:15, a QR that resolves, the deck opening offline from one file, and two captures taken after the last edit.

30-second read

  1. Nine slides, fixed time boxes, 300s total; slide 8 gets 50s.
  2. The proof slide is the point: one full-width frame, the markdown first, then the HTML artifact scrolling top to bottom at equal width.
  3. Motion is tied to meaning: assembly, branching, boundary, alarm, full scroll. No ambient loop behind the proof slide.
  4. One file, no dependencies, dark by default, letterboxed on non-16:9 projectors.
  5. There is a fallback recording and a printed URL under the QR.

Five-minute timeline

Nine ideas in three hundred seconds; the proof gets the biggest slot.

Component shape

A single file that runs offline.

One folder: deck/index.html plus local assets. No build step, no dependencies, no external fonts, no network. 16:9 stage scaled to the viewport with a transform: scale() wrapper so 1280×720 and 1920×1080 both show the same composition; on 16:10 or 4:3 projectors the stage letterboxes rather than crops.

  • Engine: ~60 lines of JS — slide array, arrow/space/Home/End nav, hash sync (#8), progress rail.
  • Motion: CSS transitions and keyframes for entrance and state changes; one requestAnimationFrame canvas for the ambient field, paused when the tab is hidden. Animation libraries are permitted (Q1: as needed) but must be vendored inline so the offline rule holds; none are required for these effects.
  • Diagrams: inline SVG with stroke-dasharray/stroke-dashoffset draw-on, per-node stagger via --i custom properties.
  • Proof images: assets/spec-md.png and assets/spec-html.png, captured headless at 1440 px wide, referenced relatively.
  • QR: static inline SVG generated offline (no network call, works with the laptop in airplane mode). R5
  • Palette: near-black #080a0d, panel #101418, ink #e8eef4, accent #35e0c0, warn #ffb545, mono #8b98a5.

The workflow (slide 2)

Slide 2 sets the stage: modern agentic development runs prompt → spec → plan → implement → review/test, and the spec is the first artifact that constrains everything after it.

A PRD states what to build for a stakeholder; a spec records the decisions that make it buildable, which is why it is the artifact worth making legible.

Decisions

Eleven decisions, each with the choice and the reason that mattered.

1 · Single-file HTML over rendered videoChose CSS/SVG/Canvas in a local folder over a Remotion MP4. Because the deck must be editable tonight between rehearsals, and a video cannot be fixed thirty seconds before a talk. Consequence: no export path; if the venue needs a file, screen-record it.
2 · Nine slides, fixed time boxesChose nine over a variable deck. Because 30s per idea is the fastest a room can absorb a diagram. Consequence: anything that does not fit is cut, not compressed.
3 · Proof by screenshot, not by claimChose two real captures over a rendered mock. Because the audience already discounts assertions, and this is the one slide that has to land. Consequence: the captures must be taken from the real files at equal width, and redone if the spec changes.
4 · Motion tied to meaningChose purposeful animation over ambient spectacle. Because a deck that loops particles behind text reads as a template, not an argument. Consequence: the ambient field is low-contrast and pauses on the proof slide.
5 · Static QR, generated offlineChose an inline SVG QR over a live generator. Because conference wifi is a rumor. Consequence: the repo URL is frozen in the asset; re-print if the repo moves.
6 · Two seams onlyChose file-opens-offline and QR-resolves as the acceptance seams. Because a deck's real failure modes are a broken asset and a dead link, not a missing animation.
7 · One full-width frame, not two half-width capturesChose a single frame that switches from markdown to the scrolling artifact over side-by-side. Because at 1920 px a half-width column is illegible, and legibility is the entire point of the slide. Consequence: the audience sees one file at a time, so the caption must name it.
8 · Libraries allowed, but inlinedChose permission with a constraint over a dependency list. Because a five-minute talk cannot debug a missing CDN, and file:// must not make network calls. Consequence: any library used must be vendored locally; none is currently needed.
9 · The artifact asset is dark, like the deckChose a dark render of the HTML spec over the template's light default. Because the room is dark, the projector is bright, and a white page at full screen is a flashbang; developers also read dark by preference. Consequence: the capture is not the template's default look, so the spec must record that the dark theme is applied for the asset.
10 · Show the whole document, not the top of itChose a slow full scroll over a static crop. Because the difference being demonstrated is structural across the entire document, and a top crop can be dismissed as a hero image. Consequence: slide 8 needs 20+ seconds and a tall capture.
11 · Alarm styling, not neutral stylingChose red for unresolved questions and low scores over uniform gray. Because a neutral checklist lets a spec with three open questions look finished, which is the exact failure the talk is about. Consequence: the artifact must support a warning state, and both the artifact and the deck share it.

Out of scope

The refusals that protect this spec from growing.

  • Video export / Remotion. Not built; the deck is live HTML.
  • Presenter view across two displays. No second window; #hash navigation only.
  • Audience interaction, polls, live demo. The five minutes are scripted time.
  • Speaker script word-for-word. The deck carries beats, not a transcript.
  • Mobile layout. Projection only; 390 px is explicitly not a target.
  • Brand system. A one-off palette, not a reusable theme.

Risks R13

Four risks, each with a stated mitigation.

The proof slide depends on screenshots that may look too similar at projection distance. Mitigation: equal-scale images plus a legibility spotlight on the HTML side; if it still reads flat, crop the markdown to its densest paragraph.
Ambient motion on a projector can stutter or wash out. Mitigation: canvas capped at 24fps, low contrast, paused on text-heavy slides.
Five minutes is easy to overrun. Mitigation: the per-slide budget is in the spec; rehearse twice with a timer.
A venue machine may not have the right fonts. Mitigation: system font stack only, no webfonts.
